# [대체됨] 예약 서비스 실험 입력 파일 세트 v0.1

현재 서비스 유형은 1:1 상담 예약으로 구체화되었습니다. 테스트에는 v0.2 파일을 사용하세요.

## 구성

- `reservation_service_card_catalog_v0.1.json`: 30개 Design Card 후보. 연구자 검토용 catalog이며 기본적으로 Agent에 통째로 전달하지 않습니다.
- `reservation_service_initial_brief_TEMPLATE_v0.1.json`: 두 트랙이 공유할 초기 요구 입력 골격. 현재는 확정 요구가 부족해 실행 준비가 되지 않은 템플릿입니다.
- `track1_profile_input_TEMPLATE_v0.1.json`: 개발자 사고 프로필 연구 조건 A–D와 프로필 스키마. 실제 개발자 정보는 비워 둡니다.
- `track2_revision_input_TEMPLATE_v0.1.json`: Revision-aware 연구 조건 A–D와 결정 ledger schema. 초기 입력에는 미래 변경을 넣지 않습니다.
- `track2_heldout_change_candidates_v0.1.json`: 변경 요구 후보. 최초 설계 파일과 반드시 분리하며, 각 변경은 초기 설계 저장 뒤 한 번에 하나씩 공개합니다.

## 실행 전 규칙

1. 먼저 30개 카드 중 v1에 실제 포함할 요구를 사용자 승인으로 확정합니다. 사용자 예시는 그대로 요구사항으로 취급하지 않습니다.
2. 승인된 요구만 초기 brief로 복사하고, 미정·가정·후속 변경을 초기 입력과 분리합니다.
3. Track 1은 동일한 initial brief에 profile/검토 정책만 바꿔 넣습니다. Profile 값은 반복 관찰 근거와 사용자 확인 없이는 채우지 않습니다.
4. Track 2는 동일한 initial brief에 설계 지시 조건만 바꿔 넣습니다. held-out change catalog는 초기 모델 입력에 절대 포함하지 않습니다.
5. Gold tests와 평가 기준은 Agent가 보지 않게 연구자 전용 파일로 따로 둡니다.
6. 모든 입력 템플릿은 현재 `readyForRun=false`입니다. v1 요구, profile, change set, evaluator가 승인되기 전에는 실험 결과로 해석하지 않습니다.
