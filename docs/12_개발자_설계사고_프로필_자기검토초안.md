## 범위와 자료 처리

이 초안은 사용자가 요청한 범위에서 접근 가능한 Codex·ChatGPT 대화 중 연구 harness, 코드 흐름 학습, 제품 동작 검증과 직접 관련된 대화만 골라 작성했다. 전체 대화의 전수 검색이나 사전 등록된 표집은 아니므로, 아래 빈도는 정확한 발생률이 아니라 검토한 맥락에서의 반복 여부를 뜻한다.

근거에는 사용자 메시지만 사용했다. assistant가 먼저 제안한 내용을 사용자의 성향으로 간주하지 않았다. 성격·능력·동기·심리적 특성은 추정하지 않았다. 아래의 부작용은 프로필을 에이전트에 적용했을 때 생길 수 있는 위험 가설이며, 사용자에게서 관찰된 결함이라는 뜻이 아니다.

이번 요청은 본인의 접근 가능한 대화 기록을 요약해 이 초안을 만드는 데 대한 명시적 허가다. 이는 원문 대화 전체를 연구 자료로 영구 보관하거나, 외부에 공개하거나, 다른 모델 학습에 쓰는 동의가 아니다. 정식 실험에서의 참여 동의, 보관 기간, 원문·파생 프로필의 삭제 절차는 별도로 정하고 실행 전에 확인해야 한다. 이 파일에는 원문 대화 전체를 복사하지 않는다.

### 반복 근거가 부족한 후보

한 ChatGPT 대화에서 대화형 세션과 history 지속을 원한 요청(E1)은 확인된다. 현재 표본만으로 여러 작업 맥락에서 반복된 설계 행동이라고 하기는 어려우므로, 이번 핵심 프로필에는 넣지 않는다. 후속 대화에서 같은 선택이 반복되면 별도 근거로 검토한다.

## 실험 조건에 전달할 프로필 요약 초안

다음 문구는 프로필 후보를 실행 지침으로 옮긴 제안이며, 본인 검토 전에는 조건 파일에 넣지 않는다.

### 공통 프로필 행동

- 먼저 요청된 저장소·화면·산출물과 명시 제약을 확인한다.
- 요구를 단계, 입력·출력, 결정, 미정 사항으로 나눈다.
- 설계·구현 완료를 주장하기 전에 핵심 사용자 흐름이 실제로 작동하는 증거를 확인한다.
- 품질 결과와 token·latency·tool 비용을 별도 기록한다.
- 계획과 실제 결과가 다르면 그 차이를 재현 가능한 상태로 적고, 범위가 명확한 수정은 수행한다.

### T1-C: 직접 적용 조건에서 검토할 부작용

이 조건에서는 위 행동을 보정 지시 없이 적용한다. 추가 확인 항목을 모두 기능 요구로 받아들이거나, 전체 흐름 검증과 문서화를 필요 이상으로 확장하는지 관찰한다.

### T1-D: 보정 적용 조건 초안

같은 프로필을 쓰되 새 발견을 다음 중 하나로 분류한다.

- implement_now: 승인된 범위이며 현재 작업에 필요
- clarify: 결과가 달라지는 사용자 결정이 필요
- defer: 후속 버전에서 다룰 가치가 있으나 현재 필수 아님
- out_of_scope: 현재 brief와 실험 범위 밖

핵심 경로를 우선 검증하고, 확인하지 않은 동작은 완료로 보고하지 않는다. 이 분류는 기존 Track 1 입력 템플릿의 보정 방향과 맞추기 위한 제안이다.

## Track 1에서 사용할 때의 제한

- 이번 프로필의 단위는 참여자 1명의 관찰 기록이다. 결과는 이 사람과 이 과제·모델·환경에 대한 탐색적 단일 사례로 보고하며, 개발자 일반으로 일반화하지 않는다.
- 프로필 추출 방식은 이번 파일의 근거 규칙으로 고정한다. 실험 중 추출 방식을 바꾸지 않고, profile-use 조건 사이에는 동일한 승인 버전과 hash를 제공한다.
- 프로필 내용은 참여자가 근거, 반복 여부, 맥락, 신뢰도, 이점 및 부작용 가설을 검토한 뒤에만 승인한다.
- 현재 문서는 설계 자료다. docs/05 템플릿, research/conditions, 실제 run에는 아직 주입하지 않는다.
- 이 프로필을 수정한 뒤 실행한다면 새 profile version을 만들고, 이전 버전과 결과를 섞지 않는다.
- 원문 대화가 필요 없는 공유·보고에서는 대화 ID나 원문을 내보내지 않고, 승인된 요약과 evidence ID만 사용한다. 보관·폐기 정책은 프로토콜 승인 전에 명시한다.
