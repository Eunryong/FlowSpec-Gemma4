# 연구 문서 안내

**현재 상태: 연구 설계 초안. 실험 실행 준비가 되지 않았습니다.** 도메인 `1:1 상담 예약 서비스`, 난이도 `L2`, 실행 순서 `Track 2 → Track 1`을 정했습니다. 두 연구 질문은 따로 분석하며, Track 1은 사전 기준으로 선정·동결한 Track 2 결과물을 모든 조건의 같은 시작점으로 사용합니다. 카드 내용과 연구 입력 JSON은 승인 전 제안이며, 확정 요구사항으로 취급하지 않습니다.

## 파일의 역할

| 자료 | 역할 | 현재 상태 |
|---|---|---|
| `00`–`02` Markdown | 결정, 연구 방향, 사람이 검토할 카드 | 도메인/L2/실행 순서 확정. 카드들은 미검토 |
| `03` 카드 catalog JSON | 카드와 출처·검토 상태·연결 관계 | `readyForRun=false` |

| `05` Track 1 JSON | 개발자 프로필과 개인화 조건 후보 | 초안, consent·profile 절차 미정 |
| `09` Markdown, `10` JSON | Aside에서 제공된 프로필 초안 원본 | 복사본 보존, 미승인 |

| `06` Track 2 JSON | 변경 인식 조건과 decision ledger 후보 | 초안, 조건·프로토콜 미정 |

## 별도 서비스 프로토타입

[로컬 1:1 상담 예약 프로토타입](../prototype/counseling-booking/README.md)은 서비스 흐름을 확인하기 위한 독립 데모입니다. 현재 연구 카드의 미승인 제안을 임시 가정으로 구현했으며, 연구 brief·condition·평가 입력으로 쓰지 않습니다.

## 지금 먼저 할 일

1. `02`의 30개 카드를 하나씩 `ACCEPTED`, `PROVISIONAL`, `ASSUMPTION`, `OPEN`, `REJECTED` 중 하나로 검토합니다. 사용자 예시(`origin`)도 자동 승인하지 않습니다.
2. 상담 분야, 상담자/운영자 역할, 예약 확정·취소 정책, 시간대·용량, 수집 정보, 저장·시험 환경을 결정합니다. 카드 간 연결 때문에 서로 영향을 주는 결정은 묶어서 봅니다.
3. 승인 카드만으로 공통 v1 brief와 검증 가능한 acceptance criteria를 만듭니다. 가정과 미결정 항목은 분리하고, 연구 조건이나 숨은 변경을 공통 brief에 넣지 않습니다.
4. Track 1은 13번 문서의 본인 프로필 근거·빈도·맥락·신뢰도·부작용 가설을 검토하고, 정식 동의·보관·삭제 규칙을 정합니다. 승인 전에는 프로필을 실행 입력으로 옮기지 않습니다.
5. 각 트랙의 조건 비교표·반복 단위·평가 기준을 확정한 뒤, 이를 harness가 읽는 파일 형식으로 옮깁니다.
6. 숨은 gold tests와 Track 2 change set을 확정하고, 입력 누출 방지 및 파일 해시를 점검합니다.

이 순서가 끝나기 전에는 연구 실험을 실행하지 않습니다. 2026-10-04에 수행한 `.agent/smoke-research/` 실행은 harness 기술 확인용 임시 태스크 API이며, 상담 예약 서비스의 결과나 연구 데이터가 아닙니다.

## 운영 원칙

- 00에 적힌 확정 사실과 초안 문서의 제안을 구분합니다. 결정을 바꾸면 00에 변경 이력을 남깁니다.
- 새 결정은 카드와 JSON의 `origin`, `reviewStatus`, `decisionClass`를 함께 갱신합니다.
- Track 2를 먼저 실행하고, 사전 기준으로 고른 동일 seed를 Track 1 모든 조건에 제공합니다. 두 연구는 하나의 2×2 연구로 합치지 않습니다.
- 조건 간 비교에서는 brief, 모델, 도구, 출력 schema, token budget, 평가 기준을 고정하고, 한 run에는 조건 하나만 적용합니다.
- 품질 지표와 토큰·시간·도구 비용을 별도로 보고합니다. 합성 점수를 만들지 않습니다.
