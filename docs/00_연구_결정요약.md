# 연구 트랙 결정 요약

## 확정된 결정

- **Track 1:** 개발자 설계 사고 프로필 + 장단점 보정. **Track 2:** Revision-aware Design. 두 연구 질문과 조건 비교는 분리하되 실행은 **Track 2 → Track 1 순서**로 한다.
- Track 2 blind evaluation에서 사전 기준으로 선정·동결한 결과물을 모든 Track 1 조건의 동일한 시작점으로 제공한다. 따라서 Track 1 결과는 해당 Track 2 seed에 프로필을 추가 적용한 효과로 해석하며, 빈 brief에서의 일반적 프로필 효과로 확장하지 않는다. 선정 지표와 tie 처리 규칙은 본 run 전에 정한다.
- 두 연구를 하나의 factorial/2×2 연구로 합치지 않는다.
- 개발할 소프트웨어의 난이도는 **L2: 작지만 상태와 흐름이 있는 중간 난이도**로 정한다.
- L2의 핵심 경계: 단순 toy/CRUD보다 풍부하고, 여러 역할·서비스를 가진 production-scale 시스템보다 작아야 한다. 주요 사용자 흐름, 지속 상태, 모듈 경계가 설계 선택의 효과를 관찰할 만큼 있어야 한다.

## L2의 작업상 해석 (세부 범위는 추후 확정)

- 여러 단계의 주요 사용자 흐름이 있고, 데이터가 저장되며, 상태 전이가 존재한다.
- 서로 영향을 주는 기능·모듈이 있어 초기 설계 선택이 이후 변경이나 예외 처리에 영향을 줄 수 있다.
- 실패·경계 조건을 검토할 만큼은 복잡하지만, 실제 결제·복잡한 권한 체계·다수의 실서비스 외부 연동 같은 변수가 실험을 지배하지 않도록 제한한다.
- LOC는 난이도의 주 기준으로 삼지 않는다. 기능 흐름, 상태·전이, 모듈 간 의존, 검증 가능한 결과를 우선한다.

## 아직 확정되지 않은 항목

- 주요 사용자 흐름·상태·모듈의 구체적 개수
- 구현·변경 평가 단계의 세부 방식
- 각 트랙의 최종 연구 질문과 실험 프로토콜

## 확정된 도메인 선택

- 두 독립 연구 트랙의 공통 도메인으로 **1:1 상담 예약 서비스**를 선택한다.
- 이전에 선택한 작업 스케줄러 도메인은 사용자가 예약 서비스로 변경해 **대체된 결정**이다.
- L2 난이도는 유지한다. 상담 분야와 v1 기능 범위는 미정이며, 설계 카드는 초안 단계다.
- 앞서 작업 스케줄러에 대해 승인한 로컬 결정론적 실행 방식과 one-shot `run_at` 예약은 해당 도메인에만 붙은 결정이다. 예약 서비스에 자동 적용하지 않으며, 테스트 실행 모델은 필요하면 다시 정한다.

## 아직 미정

- v1에 포함할 예약 흐름과 Reservation 상태
- 단일/복수 담당자·공간 및 수용량 모델
- 즉시 확정·승인·취소·변경 정책
- 로그인 방식, 시간 기준, 저장 방식과 시험용 실행 환경
- Design Card 중 확정 요구·가정·후속 변경으로 둘 항목

**다음 단계:** 예약 서비스 v1 Design Card 초안을 검토하고, 명시 요구·가정·미결정 질문·후속 변경 후보를 구분한다. 이 요약은 확정된 결정만 기록하고, 세부사항은 미결정으로 남긴다.


## 테스트 입력 파일 상태

- 30개 카드 catalog와 공통 initial-brief 템플릿, Track 1 프로필 조건 템플릿, Track 2 revision-aware 조건 템플릿을 별도 파일로 작성했다.
- 후속 변경 후보는 initial brief와 별도 파일에 격리했다.
- 모든 입력은 아직 `DRAFT / NOT READY FOR EXPERIMENT`. 예시를 확정 요구로 승인하고 평가 기준을 고정하기 전까지 실제 연구 결과로 해석하지 않는다.
